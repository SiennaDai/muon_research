## 6. Cell 4 — 两个 4096 run（C → GPU0，C3 → GPU1）

```python
import json, os, subprocess, threading, time
from pathlib import Path
import torch

CHECKOUT = "/kaggle/working/benchmark-experiments"
OUT = Path("/kaggle/working/runs")
NGPU = max(1, torch.cuda.device_count())
print("visible GPUs:", NGPU)

PLAN = [
    (0, "recipes/recursive_muon_plan_c3b6_4096_s1.json", "plan_c3b6_4096_s1"),
    (1, "recipes/recursive_muon_plan_c3_4096_s1.json", "plan_c3_4096_s1"),
]
RUN_IDS = [run_id for _, _, run_id in PLAN]

by_gpu = {}
for gpu, recipe, run_id in PLAN:
    by_gpu.setdefault(gpu % NGPU, []).append((recipe, run_id))
print("assignment:", {g: [r for _, r in items] for g, items in by_gpu.items()})

def worker(gpu, items):
    env = os.environ.copy()
    env.update({
        "DATA_ROOT": "/kaggle/working/muon_data",
        "OUTPUT_ROOT": str(OUT),
        "MAX_WALL_SECONDS": "39600",
        "KAGGLE_INSTALL_DEPS": "0",
        "KAGGLE_GPU_INDEX": str(gpu),
    })
    for recipe, run_id in items:
        if (OUT / run_id / "summary.json").exists():
            print(f"[gpu{gpu}] {run_id} already complete, skipping", flush=True)
            continue
        print(f"[gpu{gpu}] launch {run_id}", flush=True)
        subprocess.run(["bash", "scripts/run_kaggle.sh", recipe, run_id],
                       cwd=CHECKOUT, env=env, check=True)

def last_eval(run_id):
    path = OUT / run_id / "metrics.jsonl"
    if not path.exists():
        return None
    last = None
    with path.open() as fh:
        for line in fh:
            event = json.loads(line)
            if event.get("event_type") == "eval":
                last = event
    return last

threads = [threading.Thread(target=worker, args=(g, items), daemon=True)
           for g, items in by_gpu.items()]
for thread in threads:
    thread.start()
while any(thread.is_alive() for thread in threads):
    parts = []
    for run_id in RUN_IDS:
        event = last_eval(run_id)
        parts.append(f"{run_id}: {event['completed_updates']}/{event['nll']:.4f}"
                     if event else f"{run_id}: -")
    print(" | ".join(parts), flush=True)
    time.sleep(60)
print("runs finished", flush=True)
```

import json
from pathlib import Path

    ("C", 0): 4.7756,       ("C", 1): None,
    ("C3", 0): 4.8061,      ("C3", 1): None,
    ("FP32", 0): 4.6844,    ("FP32", 1): 4.6808,

RUNS = {"C": "plan_c3b6_4096_s1", "C3": "plan_c3_4096_s1"}
for name, run_id in RUNS.items():
    path = OUT / run_id / "summary.json"
    if path.exists():
        s = json.loads(path.read_text())
        REF[(name, 1)] = s["final_validation_nll"]
        print(f"{name} s1: nll {s['final_validation_nll']:.4f} "
              f"bits {s['optimizer_state']['muon_effective_bits_per_value']:.4f}")

print()
print(f"{'method':10s} {'bits':>7s} {'s0':>8s} {'s1':>8s} {'mean':>8s} {'spread':>8s}")
for name, bits in (("FP32", 32.0), ("VQ-3.49", 3.4886), ("C", 3.2315), ("C3", 2.7313)):
    a, b = REF[(name, 0)], REF[(name, 1)]
    if b is None:
        print(f"{name:10s} {bits:7.3f} {a:8.4f} {'-':>8s} {'-':>8s} {'-':>8s}")
    else:

## 8. 判读

| 结果 | 结论 |
|---|---|
| C 两 seed 均值 ≈ 基线两 seed 均值（差 ≤0.01） | **3.23 bit 与 3.49 基线统计等价**，可以写成主结论 |
| C 比基线均值差 0.01–0.02 | 3.23 bit 有小的但真实的代价，报告里如实给 |
| C3 均值比基线高 0.02–0.05 | 2.73 bit 的长期代价，作为“存储优先”的已知折扣 |
| C 的 seed 跨度 > 0.03 | 说明单 seed 不可靠，需要第三个 seed 才能定论 |

另外看 eval 曲线中 C/C3 与各自 s0 的差距是否一致——如果 s1 的 C−C3 差值与 s0 的 0.0305 接近，
说明“0.5 bit 的长期代价”是稳定量，而不是 seed 偶然。

## 10. 两 seed 实测结果

| method | bits | s0 | s1 | 均值 | span | 相对基线均值 |
|---|---:|---:|---:|---:|---:|---:|
| FP32 | 32 | 4.6844 | 4.6808 | 4.6826 | 0.0036 | −0.090 |
| VQ-3.49（基线） | 3.4886 | 4.7584 | 4.7869 | **4.7727** | 0.0285 | — |
| INT4 | ≈4.25 | 4.7746 | 4.7947 | 4.7847 | 0.0201 | +0.012 |
| **C** | 3.2315 | 4.7756 | 4.7536 | **4.7646** | 0.0219 | **−0.008** |
| **C3** | 2.7313 | 4.8061 | 4.7949 | 4.8005 | 0.0112 | +0.028 |

逐 seed 配对差：

| 对比 | s0 | s1 | 均值 |
|---|---:|---:|---:|
| C − VQ | +0.0172 | −0.0333 | **−0.0080** |
| C3 − VQ | +0.0477 | +0.0080 | +0.0279 |
| C3 − C | +0.0305 | +0.0413 | **+0.0359** |

结论：

1. **C 与 3.49 基线统计等价**：均值低 0.008，但逐 seed 差符号翻转（+0.017 / −0.033），
   说明 seed 是主变量；在少 0.26 bit（状态小 7.4%）的前提下成立。
2. **C 比 INT4 好**：均值低 0.020（4.7646 vs 4.7847），少约 1 bit（状态小 24%）。
3. **C3 的代价是稳定的**：比基线高 0.028，比 C 高 0.036（s0/s1 都是 +0.03~0.04），
   但比 INT4 只差 0.016。
4. 两个 seed 仍不足以给置信区间；要更强的统计结论需要 3–5 个 seed。
