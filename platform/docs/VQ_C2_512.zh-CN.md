# VQ C2 512 步 Runbook（3.0 bit 附近的折中点，s0）

> 目的：补上 C3（2.7313）与 C（3.2315）之间的一个点，确认比特-质量曲线在 512 步
> 是平滑的，并为“存储优先”再提供一个比 C3 更合适的候选。
>
> **先修正一个数**：上一条里说的“V/O 用 6-bit、其余 5-bit”实际只有 **2.81 bit**
> （6-bit 只作用在 V/O 的 16.7% 参数上，只加 +0.083 bit）。要让 C2 真正落在 C3 与 C 中间，
> 选择 **attention 全部 6-bit、MLP 保持 5-bit** → **2.8984 bit/scalar**。

## 10. 实测结果（s0，512 步）

| run | bits | @512 |
|---|---:|---:|
| base | 3.4886 | 5.6809 |
| C | 3.2315 | 5.6840 |
| C3 | 2.7313 | 5.6922 |
| **C2** | **2.8984** | **5.6958** |

**C2 比 C3 差 +0.0036，尽管多用了 0.167 bit。** 曲线不是平滑插值，混合分配反而落在曲线下方。

解释：C2 与 C3 的差别只在于 attention 的 5→6 bit。离线 rel_U 上 attention 6-bit 明确更好
（QKV 0.5691→0.5476，O 0.8279→0.6934），但 512 步 NLL 反而更差——这是本项目第 4 次
“保真度升、NLL 不升”的现象；在 1e-3 学习率下，表示的任何重排都会把轨迹送到另一条路上，
0.17 bit 带来的预期收益（约 −0.002）被轨迹差异（约 ±0.005）淹没。

结论：**不把 C2 作为 3.0-bit 代表点**。比特-质量曲线只在“统一改位宽”时单调（C3→C），
混合分配不在曲线上。保留 C（3.23）与 C3（2.73）这一对即可。
